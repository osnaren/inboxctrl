# Modify Database Schema

## Context

The Prisma schema is a **composite of three files**. The final `schema.prisma` is auto-generated by `pnpm db:use` — never edit it directly. The project uses `prisma db push` (not `prisma migrate`) for schema synchronization. There are zero migration files.

## Steps

1. **Edit the base schema** at `packages/db/prisma/schema.base.prisma`. This file contains all models and the generator block but NO datasource block. Add your model, field, or relation here.

2. **Regenerate the composite schema:**

   ```bash
   pnpm db:use sqlite    # or postgres
   ```

   This reads `schema.base.prisma` + `providers/{provider}.prisma`, concatenates them, and writes to `schema.prisma`. It also updates `packages/db/src/profile.ts`.

3. **Generate the Prisma client:**

   ```bash
   pnpm db:generate
   ```

4. **Push the schema to the database:**

   ```bash
   pnpm db:push
   ```

   This loads env from `apps/web/.env` via `dotenv-cli`.

5. **Verify consistency:**

   ```bash
   pnpm db:check
   ```

   This confirms `schema.prisma` datasource matches `profile.ts` exports.

6. **If adding a repository**, create or update files in `packages/db/src/` and export from `packages/db/src/index.ts` using explicit named exports.

## Gotchas

- **NEVER edit `schema.prisma` directly** — it's auto-generated. Your changes will be overwritten on the next `pnpm db:use`. Always edit `schema.base.prisma`.
- **No migration files exist** — `prisma db push` is the default path. The `db:migrate:dev` and `db:migrate:deploy` scripts exist but are not the standard workflow.
- **SQLite vs Postgres differences** — SQLite doesn't support all Postgres types. `@db.Text` works for both but `@db.VarChar(n)` is Postgres-only. Use `String` for fields that must work on both.
- **`profile.ts` must stay in sync** — `pnpm db:use` regenerates it. If you manually edit `profile.ts`, it will be overwritten.
- **The Prisma client is at `packages/db/src/generated/client`** — never import from `@prisma/client` directly in app code. Always import through `@inboxctrl/db`.
- **`prisma db push` is destructive for data** — it can drop columns/tables if you remove them from the schema. For production, consider `prisma migrate` instead.

## Verify

- [ ] Schema changes are in `schema.base.prisma`, not `schema.prisma`
- [ ] `pnpm db:use sqlite` succeeds without errors
- [ ] `pnpm db:generate` succeeds
- [ ] `pnpm db:push` succeeds
- [ ] `pnpm db:check` passes (profile matches schema)
- [ ] New repository exports use explicit named exports in `packages/db/src/index.ts`
- [ ] No direct `@prisma/client` imports outside of `packages/db`

## Debug

- **"Provider mismatch" error:** Run `pnpm db:check` to see the discrepancy. Then `pnpm db:use sqlite` (or `postgres`) to regenerate.
- **"Unknown field" after schema change:** Run `pnpm db:generate` to regenerate the Prisma client with the new schema.
- **`db:push` fails on Postgres:** Check `DATABASE_URL` in `apps/web/.env`. For Docker, the default is `postgresql://postgres:postgres@localhost:5432/inboxctrl?schema=public`.
