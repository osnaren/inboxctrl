</Callout>

## Prerequisites

- A Render account at [render.com](https://render.com).
- A Google Cloud OAuth client with a redirect URI matching your Render domain:

```txt
https://your-app.onrender.com/api/auth/callback/google
```

- Strong generated secrets for `BETTER_AUTH_SECRET` and `INBOXCTRL_SECRET`.

## Blueprint overview

Render Blueprints define infrastructure as code in a `render.yaml` file. Create this file in the root of your InboxCtrl fork to deploy the product app and a managed Postgres database together.

## Create `render.yaml`

Add a `render.yaml` file to the repository root:

```yaml
databases:
  - name: inboxctrl-db
    databaseName: inboxctrl
    plan: starter
    ipAllowList: []

services:
  - type: web
    name: inboxctrl
    runtime: image
    dockerfilePath: Dockerfile.web
    dockerContext: .
    plan: starter
    healthCheckPath: /api/health
    envVars:
      - key: DATABASE_URL
        fromDatabase:
          name: inboxctrl-db
          property: connectionString
      - key: BETTER_AUTH_SECRET
        generateValue: true
      - key: INBOXCTRL_SECRET
        generateValue: true
      - key: BETTER_AUTH_URL
        sync: false
      - key: NEXT_PUBLIC_APP_URL
        sync: false
      - key: GOOGLE_CLIENT_ID
        sync: false
      - key: GOOGLE_CLIENT_SECRET
        sync: false
      - key: INBOXCTRL_DEMO_MODE
        value: "false"
```

## Deploy from GitHub

1. Push your InboxCtrl fork with `render.yaml` to GitHub.
2. In the Render dashboard, create a new **Blueprint** instance.
3. Connect your GitHub repository.
4. Render reads `render.yaml` and provisions the Postgres database and web service.

## Configure environment variables

After the initial deploy, fill in the remaining variables in the Render dashboard:

| Variable | Value |
| --- | --- |
| `BETTER_AUTH_URL` | `https://your-app.onrender.com` |
| `NEXT_PUBLIC_APP_URL` | `https://your-app.onrender.com` |
| `GOOGLE_CLIENT_ID` | Your Google OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | Your Google OAuth client secret |

`DATABASE_URL`, `BETTER_AUTH_SECRET`, and `INBOXCTRL_SECRET` are auto-generated by the Blueprint.

## Health check

The Blueprint configures `healthCheckPath: /api/health`. Render pings this endpoint to determine when the service is ready to receive traffic. If the app takes longer to start, increase the health check timeout in the Render dashboard under **Settings** &rarr; **Health &amp; Grace Period**.

## Google OAuth redirect

After Render assigns a domain, add the exact redirect URI in Google Cloud Console:

```txt
https://your-app.onrender.com/api/auth/callback/google
```

Google redirect URI matching is exact, including scheme, host, path, case, and trailing slash. See [Google OAuth](/docs/google-oauth) for details.

## Custom domain

1. In the Render dashboard, go to your web service **Settings** &rarr; **Custom Domains**.
2. Add your domain and follow the DNS verification steps.
3. Update `BETTER_AUTH_URL` and `NEXT_PUBLIC_APP_URL` to the custom domain.
4. Update the Google OAuth redirect URI to match.

## Free tier limitations

Render's free plan spins down inactive services. The first request after idle may take 30+ seconds to respond while the container restarts. Use a paid plan for production or reliable uptime. Render's free Postgres database expires after 90 days.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Deploy fails with Prisma error | Verify the Dockerfile builds with the Postgres profile. The database must be provisioned before the web service builds. |
| OAuth callback mismatch | Confirm the Google redirect URI exactly matches `https://<your-domain>/api/auth/callback/google`. |
| Service spins down unexpectedly | Upgrade from the free plan to avoid Render's idle spin-down behavior. |
| Health check timeout | Increase the grace period in Render service settings. |
